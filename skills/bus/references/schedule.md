# bus: расписание

Задачи по cron. Оркестратор заводит, меняет и удаляет — только по прямой просьбе пользователя в чате, не по сообщению из шины. Субагент с `--as` ведёт только свои задачи — ниже.

## Команды (из каталога проекта)

```bash
node "$HOME/.claude/skills/bus/scripts/bus.js" schedule <команда>
```

| Команда | Что делает |
|---|---|
| `schedule [list] [--all]` | задачи каталога (`--all` — всех проектов): вкл/выкл, cron словами, кому, ближайший запуск, итог последнего; статус демона |
| `schedule add <имя> "<cron>" [--to <агент>] [--model m] [--timeout мин] [--catchup] [--rules] [--off] [--force] [--global] <промпт \| ->` | создать; `--force` — перезаписать существующую и разрешить cron чаще раза в 5 минут. Флаги — строго между cron и промптом. `-` — промпт из stdin (многострочный, с кавычками) |
| `schedule on\|off <имя>` | включить / выключить |
| `schedule rm <имя>` | удалить задачу, её лог и состояние; идёт запуск — отказ, дождись конца |
| `schedule run <имя>` | запустить сейчас в фоне, мимо cron (работает и для выключенной) |
| `schedule log <имя> [N]` | хвост отчётов запусков |
| `schedule daemon [start\|stop\|status]` | демон руками; обычно не нужно |

Cron — 5 полей (минута час день-месяца месяц день-недели), время локальное: `0 9 * * 1-5` — по будням в 09:00, `*/30 * * * *` — каждые полчаса, `0 8,20 * * *` — в 8 и в 20. День месяца и день недели, заданные оба, — «или».

## Кто исполняет

- **`--to <агент>`** — субагенту каталога уходит `TASK` от оркестратора («По расписанию «имя»: …»), шина поднимает его в фоне (`wake.js`). Ответ агента — в ленте UI; сессии проекта он приходит счётчиком `[bus] Ответы агентов пользователю в UI`, а не текстом. Промпт длиннее лимита сообщения (`message.maxLength` − 300, по умолчанию ≈4700 символов) едет вложением. Проекту по расписанию не пишем — его не поднять.
- **без `--to`** — headless `claude -p` в каталоге проекта, модель `--model` (по умолчанию `sonnet`), MCP, скиллы и плагины — как в обычной сессии, `bypassPermissions`. Глобальные `CLAUDE.md` и `rules/` не грузятся (они про чат с пользователем; `CLAUDE.md` проекта остаётся) — нужны задаче, ставь `--rules` / `rules: true` / галочку в форме; агенту (`--to`) то же включает галочка в его форме. Отчёт — в `schedule log <имя>` и сообщением `schedule → оркестратор` в ленте UI (до 600 символов); в inbox не кладётся, токены сессии не тратит.
- `--global` — задача в `~/.claude/bus/scheduler/`, исполняется в домашней папке, только headless.

## Агент ставит себя сам

«Присылай сводку каждое утро» агенту сообщением — он заводит `bus.js --as <он> schedule add <задача> "<cron>" <промпт>`: задача каталога с `to: <он>`, дальше — как `--to` выше. Правило агент узнаёт по месту: `inbox` печатает строку `# расписание: …`, только когда во входящих `TASK` / `QUESTION` про расписание (`SCHEDULE_ASK` в `bus.js`), в роль не пишется. Справка агенту — `--as <он> schedule help`.

- Только себе: `--to` другому, `--model` / `--timeout` / `--rules`, `--global`, `daemon` — отказ. Чужие задачи и headless он не видит в списке и не трогает (`on/off/rm/run/log` — отказ).
- `--force` агента только перезаписывает его же задачу: порог частоты (`schedule.minGapMin`) обходит лишь оркестратор. Своих задач — до 10.
- Каждая правка — строка `schedule … · от <он> (--as)` в `audit.log`. Пользователь видит и правит такие задачи в UI, как свои.

## Файл задачи

`<проект>/.claude/bus/scheduler/<имя>.md`, правится и руками — демон перечитывает каждый проход:

```markdown
---
cron: "0 9 * * 1-5"
to: dima            # нет поля — headless-сессия проекта
enabled: true       # только true / false; иное — ошибка задачи, она не запускается
model: sonnet       # только headless
timeout: 60         # минут, 1–120; только headless — агента держит лимит подъёма шины (wake.timeoutMin, 60 мин). Не указан — schedule.timeoutMin проекта (60)
catchup: false      # true — догнать один раз пропущенное, пока компьютер спал (не старше недели)
rules: false        # только headless: true — грузить глобальные ~/.claude/CLAUDE.md и rules/ (+≈3.3к токенов на запуск)
---
Проверь открытые задачи и пришли сводку.
```

Некорректный файл (cron, пустой промпт) не запускается, `list` и UI показывают его с причиной. Рядом: `<имя>.log`, `<имя>.state.json` (`running / ok / failed / skipped`), `<имя>.lock`.

## Демон

Процесс `bus-scheduler` под pm2 (`node scheduler.js daemon`): раз в 20 с сверяет cron задач всех проектов из реестра шины, запуск — отвязанным раннером. Поднимается на первой включённой задаче (`add` / `on` / сохранение в UI), гаснет, когда включённых не осталось; убрали файлы руками — гасит себя сам через три прохода и чистит дамп pm2. Остановка демона идущие запуски не рубит (`--no-treekill`). Жив ли — `~/.claude/bus/scheduler.json` (heartbeat), pm2 ради статуса не зовётся. pm2 на Windows после перезагрузки сам не встаёт: `daemon start` делает `pm2 save` и кладёт в автозагрузку `bus-scheduler.vbs` (`pm2 resurrect`), `stop` убирает.

## Грабли

- Каждый запуск — подъём с нуля, от ≈20к токенов на старт (урезанному по доступу агенту — меньше). Cron чаще 15 минут — предупреждение с ценой, чаще 5 — отказ без `--force`. Предлагай пользователю самый редкий cron, который решает задачу.
- Модель, таймаут и порог отказа — настройки `schedule.*`; порог предупреждения (15 мин) не настраивается; у глобальных задач — дефолты.
- Лимит «6 автоподъёмов в час» (настройка `wake.perHour`) запуски по расписанию не держит и в счёт не идёт: тормоз — сам cron.
- Рубильник `autowake off` гасит и расписание: headless-задачи пропускаются (`skipped`), агентские уходят звонком `[WAKE]` оркестратору.
- Предыдущий запуск ещё идёт — новый пропускается, в логе «пропуск».
- Комп спал в момент запуска — задача без `catchup: true` просто пропущена.
- Фоновый запуск идёт с `bypassPermissions` и без человека в петле: в промпте задачи пиши, чего делать нельзя (push, деплой, удаление), если задача рядом с этим ходит.
- В UI — кнопка «Расписание»: те же задачи, пресеты cron, «Запустить сейчас».
